比照台股大盤在「三地市場深度分析」裡已有的框架，套用到 LLY（Eli Lilly）個股：量能行為、 反彈強度、均線結構、基本面同步性、機構/分析師動向、籌碼結構、低點結構，結論給機率權重 （例：洗盤 65% / 出貨 35%）並寫明升級/降級條件。

🔑 關鍵設計決策：結構化 JSON 欄位，不是 AI 寫 HTML

前一天（2026-08-04）才修過 AI 直接產生 HTML 的三個 | safe 欄位文字對比度失敗的 bug，這次新功能若再用同一種「AI 自己寫 HTML + 自己選色」的做法，等於明知風險還往同一個坑跳。 改用結構化欄位後，templates/report.html.j2 直接沿用風險矩陣既有的 risk-table/risk-level CSS class 渲染，文字顏色完全交給頁面既有的 深色主題 CSS 繼承機制，AI 完全不接觸顏色決定權——從架構上排除整類 bug，而不是靠更明確的 prompt 指示去「盼望」AI 不再犯錯。

  • lly_foundayo.wash_vs_distribution：{rows: [{dimension, observation, tendency}], conclusion, upgrade_condition, downgrade_condition}，tendency 只能是 wash/distribution/neutral/unconfirmed 四選一的英文字串。
  • scripts/report_render.py 新增 _sanitize_wash_vs_distribution()：tendency 打錯字/幻覺值收斂成 unconfirmed、非 dict 的列直接丟棄、欄位缺席也不影響渲染（比照 _safe_css_token/_sanitize_lly_foundayo 既有慣例）。
  • tests/test_report_render.py 新增 3 個測試：正常渲染、欄位缺席、tendency 幻覺值與非 dict 列的防呆。
